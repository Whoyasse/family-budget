# План миграции данных: Google Sheets → Supabase

Этот план намеренно не меняет действующий источник операций. Пока миграция не завершена и проверена, приложение продолжает читать и записывать операции через Google Apps Script.

## Текущие точки работы с Google Sheets

Единственная интеграция с таблицей находится в `src/App.jsx`:

- `API_URL` — URL Google Apps Script.
- `refreshTransactions()` — читает операции через JSONP (`GET ?callback=…`), нормализует данные функцией `normalizeTransactions()` и кладёт их в состояние `transactions`.
- `handleSubmit()` — создаёт и обновляет операцию с `fetch(API_URL, { method: 'POST', mode: 'no-cors' })`; после этого перепроверяет результат через `refreshTransactions()`.
- `handleDeleteTransaction()` — удаляет операцию тем же Apps Script.
- `normalizeTransactions()`, `pickValue()`, `parseAmount()` — адаптируют ответы таблицы к формату приложения.

Остальные локальные настройки пока не находятся в Google Sheets:

- `src/utils/settingsStorage.js` — стартовый баланс, валюта, тема, внутренние пользователи, настройки онбординга (`localStorage`).
- `src/utils/categoryStorage.js` — категории и лимиты категорий (`localStorage`).

## Целевая модель Supabase

Все прикладные записи получают `household_id`; доступ к ним разрешается RLS только участникам соответствующей семьи. `auth.users` отвечает только за вход. Внутренние пользователи бюджета — это отдельная сущность `budget_users`, а не email-аккаунты.

| Локальная сущность | Целевая таблица | Важные поля |
| --- | --- | --- |
| Пользователь бюджета | `budget_users` | `id`, `household_id`, `name`, `avatar`, `archived_at`, `created_at` |
| Старые имена | `budget_user_aliases` | `budget_user_id`, `name` |
| Категория | `categories` | `id`, `household_id`, `name`, `type`, `icon`, `color`, `archived_at` |
| Старые названия категории | `category_aliases` | `category_id`, `name` |
| Лимит | `category_limits` | `household_id`, `category_id`, `month_key` nullable, `amount` |
| Настройки бюджета | `household_settings` | `household_id`, `currency`, `base_currency`, `starting_balance`, `theme`, `accent` |
| Операция | `transactions` | `id`, `household_id`, `budget_user_id`, `category_id`, `type`, `amount`, `occurred_at`, `comment`, `source`, `legacy_source_id` |

RLS должен проверять членство через `household_members.auth_user_id = auth.uid()` для чтения и записи. Клиент никогда не передаёт произвольный `household_id`: он берётся из `HouseholdContext` после проверки членства.

## Поэтапный перенос

1. **Стабилизировать Supabase-оболочку.** Уже сделаны вход, восстановление сессии и создание семьи RPC `create_household`. Google Sheets продолжает быть источником операций.
2. **Перенести настройки семьи.** При первом входе в домохозяйство создать/обновить одну строку `household_settings` из `settingsStorage` и стартового баланса. Показать пользователю, что локальные настройки синхронизированы, но не удалять localStorage.
3. **Перенести пользователей и категории.** Создать `budget_users` и `categories` с новыми UUID; сохранить таблицы соответствий локального id → Supabase id. Для `previousNames` создать alias-строки. Удалённые сущности переносить как архивные, не удалять историю.
4. **Перенести лимиты.** Дефолтный лимит хранить как строку с `month_key = null`; отдельные месячные переопределения — как строки с `month_key = YYYY-MM`. Вставлять только после получения Supabase id категории.
5. **Импортировать операции в режиме dry-run.** Выгрузить нормализованные Google Sheets строки через текущую функцию/скрипт в отдельный защищённый endpoint или одноразовый серверный импорт. Для каждой строки сопоставить имя пользователя и категорию с alias-таблицами; не найденные значения создают отчёт, а не тихую подстановку.
6. **Идемпотентная запись и сверка.** Каждой строке назначить стабильный ключ `source = 'google_sheets'` и `legacy_source_id` (id строки Google Sheets, либо хэш неизменяемых полей при отсутствии id). В базе нужен уникальный индекс `(household_id, source, legacy_source_id)`. Использовать upsert по этому ключу, поэтому повторный запуск не создаёт дублей. После импорта сравнить количество, суммы доходов/расходов по месяцам и несколько случайных строк с Google Sheets.
7. **Dual-read, затем dual-write.** На короткий период читать Supabase как основной источник и сверять его с таблицей в режиме диагностики. Только после совпадения переключить создание/редактирование/удаление на Supabase; не выполнять одновременную запись без идемпотентных ключей и журнала ошибок.
8. **Отключить Google Sheets.** Лишь после завершения полного импорта, как минимум одного периода реального использования на Supabase, успешной резервной выгрузки и подтверждения сверки. Затем убрать `API_URL`, `refreshTransactions()` JSONP и Apps Script CRUD отдельным PR. До этого Sheets остаётся read-only резервной копией.

## Защита от дублей и откат

- Импорт выполняется на конкретный `household_id` и пишет журнал запуска: время, исходное число строк, inserted/updated/skipped/failed.
- Повторный импорт использует уникальный legacy-ключ и upsert; "похожие" операции по дате/сумме не считаются совпадениями.
- Неуспешные сопоставления хранятся в отчёте для ручного выбора пользователя/категории.
- Перед первым импортом сделать экспорт Google Sheets и экспорт текущего `localStorage`; до успешной сверки не удалять ни один источник.

## Будущий импорт банковской выписки (первая версия)

1. Пользователь загружает CSV только в браузере; файл не считается операциями до подтверждения.
2. Показать предпросмотр строк и выбор соответствий колонок: дата, сумма, описание. Категория необязательна и по умолчанию пустая.
3. Нормализовать дату, сумму и текст описания; дать пользователю увидеть ошибки парсинга до импорта.
4. Для каждой строки создавать стабильный fingerprint из `household_id`, даты, суммы, описания и исходного имени файла/банковского id, если он есть. Уникальный индекс или таблица импортов блокирует повторную загрузку тех же строк.
5. После подтверждения создавать транзакции с `source = 'bank_csv'`, `category_id = null`; автоматическую категоризацию на этом этапе не делать.
6. Завершать импорт отчётом: импортировано, пропущено как дубликаты, строки с ошибкой.
